LoCoMo / memory_bench_platform 改动总结

本轮改动的核心目标是：让 locomo_test 从“平行工具”收敛为 memory_bench_platform 的 LoCoMo 专项派生执行层，同时把资源监控、 CPU/内存采样、统一 HTML 报告和专项诊断链纳入平台主框架。

1. 架构关系调整

  • memory_bench_platform 被明确为主框架，负责 skill、run archive、分析和统一报告。
  • LoCoMo benchmark skill 新增 locomo_test_remote external runner entrypoint。
  • locomo_test 不再被视为平行平台，而是 LoCoMo 专项执行层。
  • 这一关系已体现在 skill manifest、SKILL 文档、README 和入口解析测试中。

2. 统一报告与分析

  • 平台新增统一 run_report.html，汇总 accuracy、failure、resource、artifacts、chain diagnostics。
  • 平台可消费 locomo_test 导出的 meta.json、qa_diagnostics.json、qa_results.csv。
  • 新增 locomo_test 专项 diagnostics 分析桥和 timing 分析桥。
  • locomo_test 自己的 report.html 渲染已下沉到平台 bridge。

3. 资源监控与 CPU/内存采样

  • 平台原生 run 和 external runner 都支持 run 生命周期级后台采样，不再只是单点快照。
  • locomo_test_remote 在远端容器内持续写出 cpu_status.csv 和 mem_status.csv。
  • 平台分析优先消费这些远端 monitor 文件，用于真实被测环境的资源摘要。
  • 统一报告现在同时包含 CPU 和内存采样摘要。

4. 平台 bridge 下沉

  • runtime bootstrap 已下沉到平台：locomo_test_runtime_bridge
  • HTML report 渲染已下沉到平台：locomo_test_report_bridge
  • metrics / QA diagnostics / closure summary 已下沉到平台：locomo_test_metrics_bridge
  • timing report 已下沉到平台：locomo_test_timing
  • 并新增统一产物读取层：locomo_test_artifacts
